03 / GET STARTED

One line to connect your harnesses.

Supports macOS, Linux, and Windows 11 (PowerShell, Windows Terminal, cmd, or WSL2) with Git and two or more signed-in coding CLIs. The installer brings its own Node runtime when needed (or install via npm on Node.js 22.13+). broco setup detects installed harnesses, lets you confirm which ones can collaborate, prints live quotas, and installs the broco skill into your local hosts.

Then ask your current agent in plain language

“See which harness has quota headroom, fix the verifyToken() expiry bug in a worktree, then have another vendor review the diff.”

$ curl -fsSL https://broco.yanauto.me/install.sh | sh

Brings its own Node runtime when needed, installs into ~/.local/share/broco and ~/.local/bin/broco, needs no admin rights, and leaves existing Node/npm untouched. Interactive shells run broco setup automatically (AI agents/CI: set BROCO_NO_SETUP=1, then broco setup --allow ... --yes).

PS> irm https://broco.yanauto.me/install.ps1 | iex

Brings its own Node runtime when needed, installs into %LOCALAPPDATA%\broco and adds bin to your User Path, needs no admin rights, and leaves existing Node/npm untouched. Interactive shells run broco setup automatically (AI agents/CI: set $env:BROCO_NO_SETUP='1', then broco setup --allow ... --yes).

$ npm install -g @yanauto/broco

Uses your existing Node.js 22.13+ and global npm prefix. Run broco setup below next.

04 / IN PRACTICE

When two harnesses beat one

01Cross-vendor code review

Once your main harness finishes a patch, hand the git diff to a different model family cold, with fresh eyes on the diff alone.

02Quota-aware handoff

When your primary CLI approaches its 5-hour cap, send test fixes or refactors to another signed-in harness with headroom and keep your session moving.

03Borrow another harness’s strengths

Stay in your terminal while sending screenshots, PDFs, audio, video, or model-specific work to whichever local CLI fits best across Claude, Gemini, Codex, Cursor, and Pi.

04Parallel worktree batches

Fan out repetitive audits, migrations, or multi-module edits in isolated git worktrees so several tasks move forward while you stay focused in your main session.
